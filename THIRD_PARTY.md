license, so the licensing posture is auditable before any public release.

## Derived signature data

The two generated signature sets contain magic **byte patterns** (uncopyrightable
facts) plus **descriptions** that are copied labels from the source database.
Only the byte patterns drive detection; the labels are human-readable hints.

### signatures-generated/generated.toml  (loaded only with `--broad`)
- Derived from: `file(1)`'s Magdir (https://github.com/file/file), via
  `tools/ingest_magic.py`.
- Source license: **BSD-style** (the "file"/Ian Darwin license — permissive,
  requires the copyright notice be retained on redistribution of source).
- Posture: **shippable** with attribution. Include the file(1) copyright notice
  when redistributing this set.

### signatures-firmware/firmware.toml  (loaded by default)
- Byte patterns originally cross-referenced against: the fkie
  **firmware-magic-database** (https://github.com/fkie-cad/firmware-magic-database,
  GPL-3.0).
- Posture: **MIT-clean.** The magic byte values and offsets are facts about real
  firmware formats. The descriptions were **re-authored clean-room** by
  `tools/reauthor_firmware_desc.py` from a uniform template of our own
  (display-name + identifying magic + offset); no third-party prose is
  reproduced (the GPL-3.0 source's copied labels, DSL artifacts, and format
  annotations were all replaced). The `name` slugs are factual vendor/format
  identifiers (product and format names, not creative expression).
- History: an earlier revision carried the fkie descriptions verbatim; that text
  was removed in the re-authoring pass before any release. If regenerating the
  byte set from a source in the future, run `reauthor_firmware_desc.py` (or an
  equivalent) so descriptions stay original.
